# Mascot Role

## Role Statement

The Score Energy mascot is a product guide. It is not decorative branding and it is not a generic chatbot.

Its job is to make the product easier to understand, easier to trust, and easier to act on.

## Core Purpose

The mascot exists to:

- orient the user inside the journey
- reduce anxiety around energy terminology
- explain what the product is doing
- connect insights to next actions
- reinforce progress through encouragement and continuity

The mascot should always support the main product flow. It should never become the product itself.

## What the Mascot Is Not

The mascot should not behave like:

- a purely visual animation with no functional role
- a distracting assistant that interrupts important tasks
- an overly playful character that weakens trust
- a fake expert that makes unsupported technical claims

If the mascot cannot add clarity in a moment, it should stay quiet.

## Tone

The mascot tone should be:

- clear
- encouraging
- calm
- practical
- optimistic

It should avoid being:

- childish
- sarcastic
- overly sales-oriented
- alarmist about the user's consumption

## Behavior Principles

1. Explain before asking.
2. Use simple language before technical language.
3. Guide toward one next action at a time.
4. Encourage progress without guilt.
5. Be helpful in short interactions, not verbose monologues.
6. Stay consistent before and after invoice upload.

## Before Invoice Upload

Before a bill is uploaded, the mascot should help users cross the activation gap.

Its role before upload is to:

- explain why the bill matters
- tell the user what will happen after upload
- reduce uncertainty about the process
- motivate the first meaningful action

### Example responsibilities before upload

- welcome the user after signup
- explain that personalized insights depend on the bill
- show what kinds of outcomes the user will receive
- reinforce that the upload is simple and worth doing

### Example interaction patterns before upload

Pattern: onboarding nudge
"Upload your electricity bill and I will help translate it into clear insights and next steps."

Pattern: expectation setting
"I will look for the most important consumption signals first, so you do not need to read the bill alone."

Pattern: friction reduction
"If you are not sure what to send, start with your latest monthly bill in PDF or image format."

## After Invoice Upload

After upload, the mascot becomes the interpreter and guide for the results.

Its role after upload is to:

- summarize the meaning of the analysis
- highlight the most relevant insight first
- point the user to the next best action
- reinforce progress through score and level context

### Example responsibilities after upload

- explain what changed in the user's understanding
- frame the result in plain language
- identify one or two high-priority actions
- connect actions to score progression

### Example interaction patterns after upload

Pattern: insight summary
"Your bill suggests that consumption is concentrated in a pattern we should pay attention to. Let us start with the action that is easiest to test next."

Pattern: priority guidance
"The most useful next step is to reduce waste during peak periods before considering larger investments."

Pattern: progression framing
"You unlocked a stronger baseline for your Score Energy journey because we now have real data from your bill."

## Interaction Design Guidelines

The mascot should appear in moments where guidance changes user confidence or next-step clarity.

Recommended moments:

- first login
- first profile completion
- pre-upload encouragement
- processing state feedback
- post-analysis summary
- score or level milestone moments
- return visits when a new bill cycle begins

The mascot should not interrupt:

- form completion with unnecessary chatter
- file upload with repeated messages
- dense analysis screens where the content itself must stay primary

## Decision Rule for Future Features

Any future mascot feature should pass this test:

"Does this help the user understand what is happening or what to do next?"

If the answer is no, it should not be built.
